# Toolbox

เว็บรวม **เครื่องมือออนไลน์ฟรี** ใช้ง่าย ไม่ต้องล็อกอิน ประมวลผลในเบราว์เซอร์ (client-side) —
QR, QR พร้อมเพย์, ย่อ/แปลงรูป, จัดการ PDF, เครื่องคำนวณ (ผ่อน/BMI/VAT/ภาษี), สุ่ม, สร้างรหัสผ่าน,
วันที่/พ.ศ.-ค.ศ., แปลงหน่วย/สกุลเงิน, บาทถ้วน, ชุดเครื่องมือข้อความ ฯลฯ

มี 2 โหมดการรัน:
- **แบบ static ล้วน** (แนะนำสำหรับสาธารณะ) — โฮสต์ฟรีบน GitHub Pages ไม่ต้องมีเซิร์ฟเวอร์/ฐานข้อมูล → ดูหัวข้อ **เว็บ static** ด้านล่าง
- **แบบเต็ม PHP + MySQL** — มีบัญชีผู้ใช้ ประวัติ QR ย่อลิงก์นับคลิก ฯลฯ (รันบน XAMPP) → ดูหัวข้อถัดไป

## เว็บ static (ไม่มีฐานข้อมูล) + GitHub Pages

เครื่องมือเกือบทั้งหมดทำงานในเบราว์เซอร์ล้วน จึงสร้างเป็นเว็บ **static** โฮสต์ฟรีได้ (ยกเว้น
ย่อลิงก์/บัญชี/ประวัติ ที่ต้องมี backend จึงถูกตัดออกจากเวอร์ชัน static)

**สร้างไฟล์ static:** (ต้องเปิด XAMPP Apache+MySQL อยู่ก่อน เพราะสคริปต์ดึง HTML ที่ PHP render จริง)

```bash
node build-static.js
```

จะได้เว็บ static ครบทั้ง 14 เครื่องมือในโฟลเดอร์ **`docs/`** (ลิงก์ทั้งหมดเป็น `.html`,
สกุลเงินดึงตรงจาก `frankfurter.dev`, ไม่มีการเรียก server เลย)

**เปิด GitHub Pages:** ไปที่ repo → **Settings → Pages → Source: Deploy from a branch →
Branch: `master` / folder: `/docs`** → Save · เว็บจะออนไลน์ที่ `https://<user>.github.io/<repo>/`

**ทดสอบในเครื่อง:** `cd docs && php -S 127.0.0.1:8899` แล้วเปิด `http://127.0.0.1:8899/`

## แบบเต็ม (PHP + MySQL) — QR Studio เดิม

ระบบสร้างและจัดการ QR Code แบบพกพา — สร้าง QR จากลิงก์เอกสาร ใส่โลโก้ตรงกลาง
ปรับสไตล์/ขนาด เก็บประวัติค้นหาได้ และรองรับ QR แบบไดนามิก (เปลี่ยนปลายทาง + นับยอดสแกน)
ทำงานบน XAMPP (PHP + MySQL/MariaDB) ไม่มีโฆษณา ข้อมูลอยู่ในเครื่องคุณเอง

## เริ่มใช้งาน

1. เปิด XAMPP → Start **Apache** และ **MySQL**
2. เปิดเบราว์เซอร์ไปที่ `http://localhost/qrcode/install.php`
   - กรอกชื่อผู้ใช้ + รหัสผ่าน เพื่อสร้างบัญชีผู้ดูแล (ทำครั้งเดียว)
3. เข้าใช้งานที่ `http://localhost/qrcode/`

> บัญชีเดโมที่ตั้งไว้ตอนพัฒนา: **admin / qr123456** (แนะนำให้ติดตั้งใหม่ด้วยรหัสของคุณเอง)
> เพื่อความปลอดภัย หลังติดตั้งเสร็จควรลบไฟล์ `install.php`

## โครงสร้างไฟล์

```
config.php            ตั้งค่า DB + BASE_URL
schema.sql            โครงฐานข้อมูล (5 ตาราง)
install.php           ตัวติดตั้งครั้งแรก
login.php / logout.php  ระบบเข้าสู่ระบบ
index.php             หน้าสร้าง QR
history.php           ประวัติ + ค้นหา + สถิติ
bulk.php              แปลงหลายลิงก์พร้อมกัน
r.php                 ตัวเด้งลิงก์ไดนามิก + นับสแกน  (r.php?c=CODE)
includes/             db, auth, helpers, header, footer
api/                  save, list, get, update, delete (JSON)
assets/               css, js, ไลบรารี qr-code-styling
```

## ใช้งานโดยไม่ต้องล็อกอิน (guest)

หน้า **สร้าง QR** (`index.php`) เปิดให้ใช้ได้เลยโดยไม่ต้องล็อกอิน — สร้าง QR แบบปกติ (static)
ปรับสไตล์/โลโก้/ขนาด และดาวน์โหลด PNG/SVG ได้ · ระบบบันทึกให้อัตโนมัติภายใต้ผู้ใช้ระบบ `__guest__`
(admin ดูได้ผ่าน "ดูของทุกคน" ในหน้าประวัติ)

ต้องล็อกอินสำหรับ: QR ไดนามิก · แปลงหลายลิงก์ · ดู/แก้ไข/ลบประวัติ · สถิติ · เทมเพลต · ตั้งค่า/ผู้ดูแล
สไตล์พื้นฐานเริ่มต้นเป็น **ดำ · จุดมน · มุมมนมาก**

**สมัครสมาชิกเอง** (`register.php`, ลิงก์จากหน้าเข้าสู่ระบบ): กรอกชื่อ-สกุล + ชื่อผู้ใช้ + รหัสผ่าน
สมัครเสร็จใช้งานได้ทันที (role `staff` — เห็น/จัดการเฉพาะ QR ของตัวเอง) · admin ยังสร้าง/จัดการผู้ใช้ได้จากหน้าจัดการผู้ใช้

## Static vs Dynamic

- **Static** — ลิงก์ฝังใน QR โดยตรง สแกนแล้วเปิดทันที เปลี่ยนปลายทางภายหลังไม่ได้
- **Dynamic** — QR ชี้มาที่ `r.php?c=CODE` ระบบเด้งต่อไปปลายทาง จึง **เปลี่ยนปลายทางได้ภายหลังโดยไม่ต้องพิมพ์ QR ใหม่** และ **นับยอดสแกน** ได้

## ย้ายไปเซิร์ฟเวอร์จริง

แก้ `BASE_URL` ใน `config.php` ให้เป็นที่อยู่จริง (เช่น `https://qr.myhospital.go.th`)
เพื่อให้ QR ไดนามิกที่พิมพ์ไปแล้วเด้งถูกที่ · ลิงก์ภายในระบบใช้แบบสัมพัทธ์จึงย้ายได้ทันที

## การอัปเกรดฐานข้อมูล

เมื่อมีการแก้โครงสร้างฐานข้อมูลในอนาคต (เพิ่มตาราง/คอลัมน์/ดัชนี) ให้แก้ **ทั้งสองที่**:

1. `schema.sql` — เพิ่ม DDL แบบ idempotent (ใช้ `CREATE TABLE IF NOT EXISTS` เป็นต้น) สำหรับการติดตั้งใหม่
2. `migrate.php` — เพิ่มรายการใหม่ในลิสต์ `$migrations` (มี `check` ตรวจสอบผ่าน `information_schema` ก่อนว่ามีอยู่แล้วหรือยัง แล้วค่อย `apply`) สำหรับระบบที่ติดตั้งไปแล้วให้อัปเกรดได้

หน้า `migrate.php` (ต้องล็อกอินและเป็น role `admin`) รันซ้ำได้เสมอโดยไม่เกิดข้อผิดพลาด — รายการที่มีอยู่แล้วจะแสดงเป็น "ข้าม (มีอยู่แล้ว)"

## หมายเหตุ PDPA (ข้อมูลคนไข้)

ควรให้ QR ชี้ไป "ลิงก์ที่ต้องล็อกอิน" ไม่ฝังข้อมูลคนไข้ลงใน QR โดยตรง
